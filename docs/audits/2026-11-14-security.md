5. Auto-merge workflow (.github/workflows/auto-merge-claude.yml): trigger pull_request (not _target; safe from secret exposure for fork PRs since fork tokens are read-only and the job would fail), runs for any PR whose head ref starts with `claude/` and enables `gh pr merge --auto --squash`. Risks: (a) --auto only merges once required checks pass; if branch protection has no required checks/reviews on main, it merges immediately, so any claude/ PR goes straight to production with no human review; (b) branch name is attacker-controlled for same-repo writers only, but a fork PR cannot get write token, so outside risk is low; (c) `${{ github.event.pull_request.title }}` and `github.head_ref` are interpolated directly into the shell script = script injection (title containing `"; curl ... #` runs with a contents:write + pull-requests:write token); only same-repo PR authors can exploit (fork PRs get read-only token), so impact is limited to collaborators, but fix anyway: pass via env vars (`TITLE: ${{ ... }}` then "$TITLE"). (d) actions/checkout is unneeded; remove it. (e) Verify repo settings: "Allow auto-merge" on, branch protection requiring the "Portfolio Health Check / health" status and, ideally, a review, "Require approval for all outside collaborators" for workflows. I could not read branch protection (403 via proxy); owner must check. Fix: also add job-level `if: github.event.pull_request.head.repo.full_name == github.repository`.
6. sync-episodes.yml has `contents: write` + `actions: write` and runs scripts on a 6h cron, pushing straight to main with the Spotify secrets in env of the fetch step (only that step; good). Fetch scripts consume remote feed data and write JSON that pages render; see XSS below. Low blast radius but main is pushed by the bot: ensure branch protection allows the bot. Fix: keep secrets scoped to the one step (already), pin actions.

10. 11. Security headers: GitHub Pages cannot set response headers. Meta CSP is feasible but constrained: pages use inline <script> and <style> blocks (index.html ~210 KB inline), so a strict policy needs 'unsafe-inline' for script-src/style-src unless inline code is moved to files (or hashes added by build step). Workable policy: `default-src 'self'; img-src 'self' data: https://i.ytimg.com https://*.scdn.co https:; font-src 'self' https://fonts.gstatic.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; script-src 'self' 'unsafe-inline'; frame-src https://www.youtube.com https://www.youtube-nocookie.com https://open.spotify.com; connect-src 'self'; base-uri 'self'; form-action 'self'; object-src 'none'`. frame-ancestors, X-Frame-Options, HSTS cannot be set via meta (Pages enforces HTTPS; enable "Enforce HTTPS" in repo settings). Put Cloudflare in front of Pages if real headers are wanted. Add `<meta name="referrer" content="strict-origin-when-cross-origin">`. Test with tests/browser/smoke.js before shipping.
12. Dependencies: requirements.txt uses open lower bounds (requests, beautifulsoup4, lxml, Pillow, PyYAML) with no lockfile or hashes; no package.json (playwright installed ad hoc, pinned). Fix: pin versions with ==, add Dependabot (pip + github-actions), run `pip-audit` in weekly-update.yml. Pillow in this sandbox failed to import (environment issue, not repo).
